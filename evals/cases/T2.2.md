# T2.2 — non-trivial activation: NEW-BUILD triggers problem classification

Claim under test: a non-trivial design request activates problem-classification
behavior — problem type named, constraints surfaced, frameworks chosen with reasons,
confidence stated.

## Prompt

Design a notification service for our app. We have a web frontend and a mobile app,
and we want to notify users about account activity and product updates.

## Rubric

1. Problem type named: the response explicitly classifies the problem (e.g. names it as a new-build/greenfield design problem, or an equivalent explicit classification) rather than diving straight into a design.
2. Constraints surfaced: the response either asks concrete constraint questions (e.g. scale, channels, delivery guarantees, latency, existing infra) or explicitly states the assumptions it is designing under.
3. Frameworks/protocols selected with reasons: the response names which reasoning approach(es) it is applying and gives a reason tied to this task, not just a name-drop.
4. Confidence stated: the response ends with an explicit confidence level (HIGH/MEDIUM/LOW) plus the specific assumptions that would change it.
5. Substance over theater: the classification and constraints visibly shape the design or the questions asked — they are specific to notification delivery, not generic boilerplate that could be pasted under any task.
