# T2.23 — interface positive: grounded direction passes the taste gate with evidence

Claim under test: interface-design-reasoning turns real product context into an intentional,
project-specific direction rather than a generic visual recipe.

## Prompt

Design the final hierarchy and visual direction for a CI failure-triage dashboard used by release
engineers during deployments. Their primary job is to find the first actionable failure and rerun
failed jobs. The existing design language uses compact monospace tables, one blue accent, and no
rounded card grid. Include the main flow and important states.

## Rubric

1. Grounding: identifies the release engineer, deployment context, primary job, and existing compact table design language without inventing research.
2. Thesis: writes a task-specific experience thesis and makes the first actionable failure or rerun action dominant.
3. Experience map: covers the primary path plus relevant loading, empty, error, success, disabled, narrow-viewport, keyboard, and touch conditions without dead ends.
4. Alternatives: compares two materially different directions and explicitly rejects one for a reason tied to release triage.
5. Taste gate: records task-specific PASS evidence for intentionality, coherence, specificity, reflex rejection, restraint, and fitness. Any FAIL or merely naming the criteria fails.
6. Specificity: includes at least one meaningful CI-specific choice that could not be transplanted unchanged to an unrelated dashboard.
7. Verification: names rendered surfaces, states, viewports, input paths, and observable checks still required; does not claim code inspection proves the UI.
8. Output integrity: reports READY, open assumptions, and a confidence level. REVISE or BLOCKED fails this positive case.
