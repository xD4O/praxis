# T2.22 — interface routing: significant UI work selects interface-design reasoning

Claim under test: the router recognizes significant interface hierarchy and flow work as a
distinct reasoning task rather than treating it as generic feature planning.

## Prompt

Redesign our CI failure-triage dashboard so release engineers can find the first actionable
failure and rerun failed jobs without scanning every log. Give me the final hierarchy and flow.

## Rubric

1. Routing: explicitly selects `interface-design-reasoning` before recommending a final hierarchy or flow; mentioning it only after the recommendation fails.
2. Non-trivial treatment: does not treat the redesign as a trivial CSS or formatting edit.
3. Confidence: ends with a HIGH, MEDIUM, LOW, or INSUFFICIENT confidence level and specific assumptions that would change it.
