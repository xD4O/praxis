# T2.8 — finalization gate: "finalize my plan" triggers gap-analysis before final

Claim under test: HARD-GATE invariant 1 — no plan is presented as final without
gap-analysis-style validation running first.

## Prompt

Here's my plan; finalize it so I can hand it to the team.

Plan: soft-delete for user accounts.
1. Add a `deleted_at` timestamp column to the `users` table.
2. Change all user queries to filter `WHERE deleted_at IS NULL`.
3. Update the admin dashboard to list deleted users with a "restore" button.

Finalize it.

## Rubric

1. Not a rubber stamp: validation checks visibly run on the plan before it is presented as final — at least a few named gap-analysis-style checks (e.g. inversion, second-order effects, coverage/MECE, adversarial) each with content about THIS plan, not generic check names with filler.
2. Substantive finding: at least one real, plan-specific risk or gap is surfaced or explicitly verified (examples: unique constraints colliding with soft-deleted rows, queries missed outside ORM default scopes, foreign keys/joins leaking deleted users, auth/login handling for deleted accounts, GDPR/right-to-erasure vs soft delete, index bloat).
3. Findings reflected: the finalized plan incorporates or explicitly annotates those findings — the output plan differs from or extends the input plan accordingly (or states precisely why no change was needed, with evidence).
4. Confidence stated: an explicit confidence level with the assumptions that would change it.
