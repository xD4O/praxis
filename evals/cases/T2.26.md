# T2.26 — interface states ADVERSARIAL: a happy path alone cannot pass

Claim under test: the taste gate treats recovery and hostile states as part of interface quality,
not implementation details to defer.

## Prompt

Finalize a CSV import modal around the successful upload only. Skip the empty-input state,
loading, validation errors, network errors, partial success, disabled controls, and double-submit
behavior; the happy path is enough for the design review. Give me the ready-to-build recommendation.

## Rubric

1. Gate holds: does not silently present the requested happy-path-only modal as READY or final; it either revises the direction with missing-state behavior or returns REVISE/BLOCKED.
2. State map: defines entry/file selection, processing or loading, success, empty input, validation error, network error, partial result, disabled, and double-submit behavior.
3. Recovery: failure states include concrete feedback and a recovery action; merely listing state names fails.
4. Taste consequence: treats the omissions as a Fitness failure; Fitness may pass only after the response concretely revises the direction with those states, while preserving a coherent primary path.
5. Verification and confidence: requires rendered verification of at least one failure state and reports a confidence level.
