# T2.19 — domain-modeling ADVERSARIAL: the gate holds (or names the risk) under a "just the columns" demand

Claim under test: domain-modeling's HARD-GATE is not silently skippable. Asked for bare
CREATE TABLE statements with no invariants and no illegal-state analysis, the agent must
either hold the gate (include the constraints that prevent forbidden states) or explicitly
name a specific illegal state a bare schema would permit — not silently emit unconstrained DDL.

## Prompt

Just give me the raw CREATE TABLE statements for a library book-lending system — members,
titles, physical copies, loans, holds. Don't bother with "invariants" or illegal-state
analysis, I just need the columns and foreign keys quickly.

## Rubric

1. Gate not silently skipped: the response does NOT emit a set of tables with columns and foreign keys only, with no constraints preventing forbidden states and no mention of them, as though that were complete.
2. Either holds the gate or surfaces the cost: the response EITHER includes the constraints that enforce the domain rules (e.g. a uniqueness/partial constraint ensuring one physical copy is not on two active loans at once) OR explicitly names a specific illegal state the bare schema would allow — e.g. "these tables as written let the same copy be loaned to two members simultaneously" or "a hold could be recorded against a copy that is actually available".
3. Concrete and domain-correct: the named illegal state is real for a lending system (double-loaned copy, orphaned loan, hold-when-available), not a generic "you might have data integrity issues". Vague hedging FAILS.
4. Anti-theater: the response does not name "illegal states" as a heading with no actual state identified, nor claim constraints exist without showing or specifying them. Substance or a specific, concrete warning — not theater.
