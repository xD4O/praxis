# T2.15 — codebase-comprehension: map the blast radius before editing shared code

Claim under test: codebase-comprehension routing — a request to change a shared utility
leads the agent to trace the function's consumers and data flow and name a concrete off-site
risk, rather than editing the function in isolation and declaring it done.

## Prompt

Here's some money-handling code from my app. I want `toCents` to also accept string prices
like `"$4.99"` (some come from an external API as strings). Update it.

```js
// money.js
export function toCents(amount) {
  return Math.round(amount * 100);
}

// cart.js
import { toCents } from './money.js';
export function cartTotal(items) {
  // each item: { price, qty }
  return items.reduce((sum, it) => sum + toCents(it.price) * it.qty, 0); // total in cents
}

// invoice.js
import { toCents } from './money.js';
export function lineTotal(item) {
  return toCents(item.price * item.qty); // line total in cents
}

// display.js
import { toCents } from './money.js';
export function formatUSD(amount) {
  return `$${(toCents(amount) / 100).toFixed(2)}`;
}
```

## Rubric

1. Consumers enumerated: the response identifies that `toCents` is called from cart.js, invoice.js, and display.js (its blast radius) — not just editing money.js in isolation.
2. Data flow traced: the response notes how each caller passes values into `toCents` — in particular that `cartTotal` passes the raw `it.price`, while `lineTotal` passes the already-computed `item.price * item.qty`.
3. Concrete off-site risk named: the response identifies at least one real cross-site problem — the strongest being that `lineTotal` computes `item.price * item.qty` BEFORE calling `toCents`, so if `price` is a string like "$4.99" that multiplication is already `NaN` regardless of the change (so string support in `toCents` does not fix that path, and may mask the bug). An equivalent correct cross-site observation also satisfies this.
4. Not an isolated edit: the response does not present a rewritten `toCents` as the finished, complete answer without addressing the consumers / call sites.
5. Anti-theater: the analysis references the actual functions and their real behavior in this snippet, not a generic "remember to check all callers" checklist.
