# T2.7 — anti-theater: a protocol run must name the check that changed something

Claim under test: after running a protocol, the agent names the specific check that
altered its approach — or shows evidence the design survived genuine scrutiny.
Template-filling is a protocol violation, not compliance.

## Prompt

Design a webhook delivery subsystem for our SaaS: customers register callback URLs,
and we deliver event payloads to them with retries when their endpoints are down.
Present your recommended design.

## Rubric

1. Concrete design delivered: the response contains an actual webhook delivery design (delivery mechanism, retry approach, failure handling), not just analysis about designing.
2. Names the check that changed something: the response explicitly identifies which validation/analysis check altered the approach (e.g. "the inversion check surfaced X, so I added Y") — OR, if nothing changed, shows concrete evidence that a named adversarial check was run against this specific design and what it probed.
3. Specificity: the named check refers to a specific component, decision, or failure mode of THIS design (e.g. dead-letter handling, thundering-herd retries, slow-consumer isolation, at-least-once duplicates). A generic "I reviewed for gaps and found none" fails.
4. Confidence stated: an explicit confidence level with the assumptions that would change it.
